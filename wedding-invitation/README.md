# Артём & Юлия — сайт-приглашение

Одностраничный сайт-приглашение на свадьбу 19 сентября 2026 года. Чистый
HTML/CSS/JS без сборки и зависимостей — открывается как есть, кладётся на
любой статический хостинг.

Оформление опирается на данные скилла `ui-ux-pro-max` (подбор пары шрифтов,
акценты, чек-лист доступности) и на принципы типографики и вёрстки школы
бюро Горбунова: модульная сетка отступов, единая шкала заголовков, длина
строки под чтение (~62 символа), неразрывные пробелы после однобуквенных
предлогов/союзов, типографское тире, кавычки-«ёлочки».

## Структура

```
wedding-invitation/
  index.html
  css/style.css
  js/main.js
  assets/photos/   ← сюда кладутся реальные фотографии (см. ниже)
```

Разделы страницы: герой с датой и обратным отсчётом → программа дня
(церемония + банкет) → место проведения с картой → дресс-код с палитрой →
подарки → ведущий (контакт на случай сюрприза/истории) → RSVP (контакт) →
фотогалерея → закрывающий блок.

## 5. Как проверить и опубликовать

Локально:

```bash
cd wedding-invitation
python3 -m http.server 8080
# открыть http://localhost:8080
```

Опубликовать можно на GitHub Pages (Settings → Pages → папка
`wedding-invitation`), Netlify/Vercel (drag-and-drop папки) или любом
статическом хостинге — сборка не нужна.

При публикации обновите в `index.html`:
- `<meta property="og:image" content="assets/photos/hero.jpg" />` — на
  полный URL (`https://ваш-домен/assets/photos/hero.jpg`), иначе превью
  ссылки в мессенджерах не подтянет картинку.
- `<meta name="robots" content="noindex, nofollow" />` — сейчас страница
  закрыта от поиска (это персональная страница с адресами и телефоном,
  не публичный контент). Уберите эту строку, если хотите, чтобы её можно
  было найти в Google/Яндексе.

## 6. Автоматические тесты

Сам сайт остаётся статикой без сборки — но проверка теперь не «прогнать
руками и посмотреть скриншот», а настоящий тест-сьют на Playwright:
доступность (`axe-core`), визуальная регрессия (`toHaveScreenshot`) и
функциональные проверки (мобильное меню, счётчик, копирование хекса,
плавающая кнопка RSVP, отсутствие горизонтальной прокрутки).

```bash
cd wedding-invitation
npm install
npx playwright test              # прогнать всё
npx playwright test --ui         # в интерактивном режиме
npm run test:update-screenshots  # пересохранить эталонные скриншоты после осознанного изменения дизайна
npx playwright show-report       # HTML-отчёт последнего прогона
```

Эталонные скриншоты (`tests/*-snapshots/`) закоммичены в репозиторий —
это и есть смысл визуальной регрессии: следующий прогон сравнивается не
с «на глаз похоже», а с конкретным сохранённым пикселем. При намеренном
изменении дизайна их нужно пересохранить командой выше и закоммитить
вместе с изменением.

`playwright.config.js` жёстко указывает путь на Chromium и добавляет
`--no-sandbox` — это нужно только в контейнерах, где всё запускается от
root (как в этой среде разработки); в обычном окружении разработчика эти
строки просто не мешают.

## Что уже проверено

- Адаптивная вёрстка mobile-first, брейкпоинты 375 / 390 / 412 / 768 / 1024 /
  1440px — без горизонтальной прокрутки на любой ширине.
- iOS/Android: `safe-area-inset-*` под чёлку и жестовую полосу, размер полей
  ввода ≥16px (Safari не зумит при фокусе), все интерактивные элементы
  ≥44×44px, вязкость к `100svh/100dvh` для реальной высоты экрана с учётом
  адресной строки браузера.
- Доступность: семантическая разметка, видимый фокус с клавиатуры,
  `skip-link`, `prefers-reduced-motion` отключает анимации.
- Прогрессивное появление блоков при прокрутке проверено и на обычной
  прокрутке колесом/тачем, и на резких переходах по якорным ссылкам —
  срабатывает в обоих случаях (двойная защита: `IntersectionObserver` +
  запасная проверка позиции по скроллу).
- Палитра дресс-кода — сетка (2 колонки на телефоне, до 8 на десктопе),
  без горизонтального свайпа: жест «потянуть вбок» внутри вертикально
  скроллящейся страницы ненадёжен на мобильных (браузер может перехватить
  его как обычный скролл страницы) — все цвета видны сразу через обычную
  прокрутку вниз. Клик/тап по образцу копирует HEX в буфер обмена.
- Контраст текста проверен скриптом по всей странице (WCAG-формула,
  не на глаз) — все смысловые тексты ≥4.5:1.
- Фото галереи сжаты под их реальный размер на экране (в сетке они никогда
  не шире ~450px даже на десктопе) — было 119–396 КБ на файл при исходных
  1700px+, стало 51–140 КБ при 1100px по длинной стороне; на глаз разницы
  в чёткости нет ни на телефоне, ни на десктопе.

Тема сайта единая (тёплая, светлая) и намеренно не подстраивается под
тёмную тему устройства — так у всех гостей приглашение выглядит одинаково.
